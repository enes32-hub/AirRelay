## Corresponding source

The corresponding source is exported from this checkout by `scripts/export_source_zip.py`, which
writes a verified manifest into the archive (the export refuses to include signing material,
`local.properties`, secrets or build outputs):

| Item | Value |
|---|---|
| How to produce | `python scripts/export_source_zip.py <output.zip>` — run it for every published build |
| Contents | the whole checkout: `app/` integration source, vendored UxPlay, FFmpeg and libplist sources, the OpenSSL build wrapper, all seven UxPlay patches, build scripts, `legal/` and `gradle/libs.versions.toml` |
| Integrity | the archive contains `EXPORT_MANIFEST.json`, listing every file with its size and SHA-256; the tool re-reads the archive and refuses to report success unless every entry verifies |
| Archive hash | printed by the tool on completion. Record it in the release notes beside the published binary — **not in this file**: this notice travels inside the archive, so a hash written here could never match the archive that contains it |

## Notice texts inside the app

The licence texts and copyright notices shown under *Settings → About → Component licences* are
generated from the pinned files by `tools/build_open_source_notices.py`. Regenerate that asset
whenever a licence file or a component changes; do not edit the generated asset by hand. The
machine-readable inventory is `legal/SBOM.spdx.json`, generated by `tools/generate_sbom.py`; run it
with `--check` in CI or before a release so the file cannot silently drift from
`gradle/libs.versions.toml` and the native component list.
